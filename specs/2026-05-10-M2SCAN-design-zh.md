# ClusterMamba 设计规格书

**日期：** 2026-05-10（更新于 2026-06-09）
**状态：** 草案（重大更新：编码器切换为纯 CCSM，模块命名重新设计）
**目标：** 医学图像分割

---

## 1. 概述

ClusterMamba（Cluster-Centric Mamba）是一种用于医学图像分割的全链路 cluster-centric U-Net 架构。编解码两端统一采用 `聚类→Mamba扫描→扩散` 的计算范式——每层先将 H×W 个像素特征压缩为 K 个聚类质心，仅在 K 个质心上运行 Mamba S6 进行全局推理，再将学习到的全局上下文扩散回每个像素。跳跃连接门控（CG）通过复用聚类质心实现零额外参数的全局感知筛选。

### 1.1 核心思路

用 **CCSM**（聚类中心扫描模块）替换 EMCAD 编码器中的 PVTv2 Transformer 块和解码器中的 MSCAM；用 **CG**（Cluster-Gate，质心复用门控）替换 **LGAG**（大核分组注意力门控）；用 **Patch Expanding** 替换 **EUCB**（高效上卷积模块）。编解码器共享同一 CCSM 计算范式，解码器额外配备 SA（空间注意力）和 CA（通道注意力）细节补偿分支，组成 **CS-CCSM** 解码器模块。

| 组件 | EMCAD（基线） | ClusterMamba（本文） |
|------|-------------|---------------------|
| 编码器 | PVTv2 (Transformer) | CCSM 编码器（纯 CCSM 堆叠，K=[8,6,4,2]） |
| 解码器核心 | MSCAM（深度可分离卷积注意力） | CS-CCSM（CCSM + SA + CA，K=[2,4,6,8]） |
| 跳跃连接门控 | LGAG（大核分组注意力） | CG（质心复用门控） |
| 上采样 | EUCB（高效上卷积） | Patch Expanding（与 Patch Merge 对称） |
| 多级损失 | 是 | 是（保留） |

### 1.2 创新点

1. **聚类中心扫描模块（CCSM）：** 编解码共用的核心模块，以 K 个聚类质心替代 H×W 个像素进行 Mamba S6 全局推理。编码器纯 CCSM 堆叠（K=[8,6,4,2] 递减），解码器在 CCSM 基础上融合 SA + CA 组成 **CS-CCSM**（K=[2,4,6,8] 递增），实现从细粒度结构到粗粒度语义的层次化全局上下文建模。

2. **全链路 Cluster-Centric 架构：** 编码器和解码器统一采用 CCSM 作为基本构建块，共享 `cluster→scan→diffuse` 计算范式。Mamba S6 仅扫描 K 个聚类质心（K ≪ H×W），从架构层面消除逐像素扫描的冗余。首个编解码全链路统一采用聚类中心扫描范式的分割网络。

3. **质心复用门控（CG）：** 将 CS-CCSM 产出的聚类质心复用于跳跃连接门控——质心不仅用于全局上下文扩散，还指导编码器特征的智能筛选。同一组质心，双重用途。零额外参数替换 LGAG 的大核卷积。

4. **对称编解码设计：** 编码器使用 Patch Merge 下采样，解码器使用 Patch Expanding 上采样，两者互为逆操作。K 值在编码器递减（细→粗）、解码器递增（粗→细），形成镜像对称的粒度层级。

## 2. 架构设计

### 2.1 整体网络结构

```
输入 (H×W×3)
    │
    ▼
┌────────────────────────────────────┐
│  Conv Stem (stride=4, 3→64)        │
└────────────────────────────────────┘
    │
    ├── Stage 1: CCSM ×2 (K=8)  ──── X1 (64ch, H/4)
    │       ↓ Patch Merge
    ├── Stage 2: CCSM ×2 (K=6)  ──── X2 (128ch, H/8)
    │       ↓ Patch Merge
    ├── Stage 3: CCSM ×8 (K=4)  ──── X3 (256ch, H/16)
    │       ↓ Patch Merge
    ├── Stage 4: CCSM ×2 (K=2)  ──── X4 (512ch, H/32)
    │
    ▼
┌──────────────────────────────────────┐
│  Bottleneck: CCSM ×2 (K=2)           │
└──────────────────────────────────────┘
    │
    ▼  (H/32, 512ch)
┌──────────────────────────────────────────────┐
│  解码器 Stage 4:                              │
│    CS-CCSM(K=2) → CG(X4) → p4                │
│                    ↓                         │
│             Patch Exp ↑2× (H/32 → H/16)      │
│  解码器 Stage 3:                              │
│    CS-CCSM(K=4) → CG(X3) → p3                │
│                    ↓                         │
│             Patch Exp ↑2× (H/16 → H/8)       │
│  解码器 Stage 2:                              │
│    CS-CCSM(K=6) → CG(X2) → p2                │
│                    ↓                         │
│             Patch Exp ↑2× (H/8 → H/4)        │
│  解码器 Stage 1:                              │
│    CS-CCSM(K=8) → CG(X1) → p1                │
└──────────────────────────────────────────────┘
    │
    ▼
最终分割图 (H×W×#classes)
```

### 2.2 编码器：纯 CCSM 堆叠

编码器由 4 个 Stage 组成，每个 Stage 由 N 个 **CCSM** 模块直接堆叠（无额外 FFN），后接 Patch Merge 下采样。Bottleneck 额外追加 2 个 CCSM（K=2，不下采样）。

**CCSM 模块结构：**
```
Input → CCSM(K) → Output
        └─ Feature Aggregating → S6 Scan over K centroids → Score Diffusing ┘
```

CCSM 是自包含的完整模块，内部包含：
- Pre-projection（通道投影 + DWConv 空间混合）
- Feature Aggregating（聚类为 K 个质心）
- Mamba S6（仅在 K 个质心上做选择性子扫描）
- Score Diffusing（相似度软分配扩散回 H×W 像素）
- Output projection + Gate modulation

与旧 VSS Block（LN→SS2D→LN→FFN）不同，CCSM 不需要外部 FFN 包装。

| 属性 | VSS Block（旧，VMamba 借用） | CCSM（新，ClusterMamba 编码器） |
|------|---------------------------|------------------------------|
| 空间混合 | SS2D（4方向像素扫描） | CCSM（聚类→扫描→扩散） |
| 扫描对象 | 像素序列 (H×W tokens) | K 个聚类质心 |
| 外部 FFN | 需要 | 不需要（CCSM 自包含） |
| K 值 | 无 | [8, 6, 4, 2] 随分辨率递减 |

- 通道数：64 → 128 → 256 → 512
- Block 分布：[2, 2, 8, 2]（Stage 3 最深，H/16 分辨率是聚类质量与计算量的平衡点）
- 下采样：Patch Merge（2×2→1，通道翻倍）
- **编码器 CCSM 不含 SA/CA**：编码器职责是语义抽象；细节通过跳跃连接传递到解码器，由解码器的 SA + CA 负责恢复

### 2.3 解码器：CS-CCSM + CG

解码器共 4 级。Stage 4 直接取瓶颈输出（H/32），无需上采样（Xi=X4 也在 H/32）。后续每一级先用 Patch Expanding 翻倍分辨率，再匹配对应的编码器跳跃连接。

每个解码器层级的流程：

```
  上一级输出
       │
       ▼
  ┌──────────────┐   (Stage 4 跳过此步)
  │ Patch Expand │
  └──────┬───────┘
         │
         ▼
  ┌────────────────────────┐
  │     CS-CCSM(K)         │
  │  = CCSM + SA + CA      │
  │  (内部产出质心参数)      │
  └───────┬────────────────┘
          │
    ┌─────┴─────┐
    ▼           ▼
  F_out       CG(Xi)
    │           │
    │           ▼
    │       Xi' (门控后)
    │           │
    └─────┬─────┘
          ▼
   融合 + SegHead → p_i
```

**Patch Expanding（上采样模块）：**
- Linear(C → 2C) → PixelShuffle(H×W → 2H×2W) → Linear(2C → C/2)
- 与编码器的 Patch Merge 互为逆操作，形成对称编解码设计

**CS-CCSM(K) = CCSM + SA + CA：**
- CCSM 前置执行，输出特征图 F_out 和质心参数 Ĉ, W
- SA（空间注意力）和 CA（通道注意力）并行运行，补偿聚类过程中丢失的细节
- Ĉ, W 送给 CG（Cluster-Gate）复用

**CG（Cluster-Gate，质心复用门控）：**
- 输入 Xi（编码器跳跃连接），内部使用 CS-CCSM 的质心参数 Ĉ, W 计算门控系数
- 不产生新特征，只输出 Xi' = Xi ⊙ gate，筛掉噪声像素

对跳跃连接特征 Xi 的每个空间位置 p：
1. 计算 p 与 K 个质心的余弦相似度：`sim(Xi_p, ĉₖ)`
2. Softmax 得到归属概率：`α_{p,k} = softmax(α·sim + β)`（α, β 复用自 CS-CCSM）
3. 质心全局权重加权求和：`g_p = Σₖ α_{p,k} · wₖ`（wₖ 来自 Mamba S6）
4. Sigmoid 门控：`Xi'_p = Xi_p · σ(g_p)`

**直觉：** Mamba S6 输出的 wₖ 代表"第 k 个聚类有多重要"。如果一个 skip 像素属于重要质心，门控权重就大，信息被保留；反之被抑制。门控获得了整张图的全局语义理解。

**SegHead（分割头）：** 1×1 卷积，将特征通道映射到类别数。

**多级损失：** L = Σ L(p_i) + L(Σ p_i)，沿用 EMCAD 的 MUTATION 组合损失。

### 2.4 CG 与 LGAG 对比

| 维度 | 原 LGAG | CG（Cluster-Gate） |
|------|--------|-------------------|
| 感受野 | 大核卷积（局部） | 全局（质心代表整图） |
| 门控依据 | 卷积特征响应 | 聚类归属 + 质心全局重要性 |
| 额外参数 | 大核卷积权重 | 几乎为零（复用 Ĉ, α, β, W） |
| 与 CS-CCSM 关系 | 独立模块 | 紧密耦合，共享质心 |

### 2.5 CS-CCSM 内部结构

```
F_in ──┬──► CCSM(K) ──► 全局上下文 F_out, 质心 Ĉ, 权重 W ──┐
       │                                                      ├──► 融合 ──► 最终输出
       ├──► SA ────────► 空间细节 ───────────────────────────┤
       └──► CA ────────► 通道细节 ───────────────────────────┘
```

- **CCSM(K)：** 将 H×W 个像素特征通过相似度软分配提炼为 K 个聚类质心 Ĉ；仅在这 K 个质心上运行 Mamba S6 进行全局推理，输出质心权重 W；将质心级全局上下文通过相似度分布扩散回所有像素。K 控制聚类粒度。**同时输出 Ĉ 和 W 供 CG 复用。**
- **SA（空间注意力）：** 在空间维度上计算注意力，增强对位置敏感的特征响应（边缘、小目标）。
- **CA（通道注意力）：** 在通道维度上计算注意力，自适应调整各通道的重要性权重。
- SA 和 CA 并行运行，结果与 CCSM 的全局上下文输出融合，补偿聚类过程中丢失的高频细节。

### 2.6 多尺度 K 策略与编解码对称

**编码器（K 随分辨率递减，细→粗）：**

| 编码器层级 | 分辨率 | K | 含义 |
|-----------|--------|---|------|
| Stage 1 | H/4 | 8 | 细粒度：需要最多质心表示局部纹理和边界 |
| Stage 2 | H/8 | 6 | 中等粒度 |
| Stage 3 | H/16 | 4 | 较粗粒度 |
| Stage 4 | H/32 | 2 | 粗粒度：仅需区分主要语义区域 |
| Bottleneck | H/32 | 2 | 同 Stage 4 |

**解码器（K 随分辨率递增，粗→细）：**

| 解码器层级 | 分辨率 | K | 跳跃连接 | 含义 |
|-----------|--------|---|---------|------|
| Stage 4 | H/32 | 2 | X4 (H/32, 512ch) | 粗粒度：前景 vs 背景 |
| Stage 3 | H/16 | 4 | X3 (H/16, 256ch) | 中等粒度 |
| Stage 2 | H/8 | 6 | X2 (H/8, 128ch) | 较细粒度 |
| Stage 1 | H/4 | 8 | X1 (H/4, 64ch) | 最细粒度：小结构、边界 |

K 值编解码对称，形成镜像层级：
```
Encoder: [8, 6, 4, 2]  →  Bottleneck(2)  →  Decoder: [2, 4, 6, 8]
       细 →→→→→→ 粗          最粗          粗 →→→→→→ 细
```

- 解码器 Stage 4 直接从瓶颈（H/32）进入 CS-CCSM，无需 Patch Expanding（X4 也在 H/32）
- 解码器 Stage 3–1 先 Patch Expanding 翻倍分辨率，再匹配对应层跳跃连接
- K 值与分辨率的关联逻辑：分辨率越高 → 像素多样性越大 → 需要更多质心表达

### 3.1 文件结构

```

├── models/
│   ├── __init__.py
│   ├── encoder.py          # CCSM 编码器（纯 CCSM 堆叠 + Patch Merge）+ Bottleneck
```

### 3.2 关键超参数

| 参数 | 值 | 说明 |
|------|----|------|
| 编码器 Blocks | [2, 2, 8, 2] | 每个 Stage 的 CCSM 模块数量 |
| 通道数 | [64, 128, 256, 512] | 各 Stage 通道数 |
| Encoder K 值 | S1→S4: [8,6,4,2] | Stage1(H/4)=8, Stage2(H/8)=6, Stage3(H/16)=4, Stage4(H/32)=2 |
| Decoder K 值 | S4→S1: [2,4,6,8] | 与 Encoder 镜像对称 |
| S6 d_state | 16 | Mamba 状态空间维度 |
| 预估参数量 | ~10M | vs EMCAD-B2 的 26.8M；编码器纯 CCSM，无外部 FFN/SS2D 开销 |

### 3.3 依赖

- PyTorch >= 2.0
- 纯 PyTorch 实现，无 CUDA 定制算子依赖
- timm（可选，用于训练工具）

### 3.4 训练策略

沿用 EMCAD 的训练协议：
- 优化器：AdamW，lr=1e-4，weight_decay=1e-4
- 训练轮数：200（二分类），300–400（多器官）
- Batch size：16（二分类），6–12（多器官）
- 输入尺寸：352×352（二分类），224×224（多器官）
- 多尺度训练：{0.75, 1.0, 1.25}
- 损失函数：加权 BCE + 加权 IoU（二分类）；交叉熵 + Dice（多类别）
- 梯度裁剪：0.5

### 3.5 评估方案

- 二分类分割：10 个数据集（息肉×5、皮肤病变×2、细胞×2、乳腺癌）
- 多器官分割：Synapse、ACDC
- 指标：DICE、HD95、mIoU
- 效率：参数量、FLOPs（在 224×224 和 256×256 分辨率下测量）

## 4. 风险与缓解

| 风险 | 缓解措施 |
|------|---------|
| CCSM 编码器收敛慢于 SS2D | SS2D 有 4 方向信息融合优势；通过适当增加 warmup epoch 和学习率调优弥补 |
| CCSM 在 K > sqrt(H×W) 时退化 | 保护逻辑：K = min(K, sqrt(H×W)) |
| Mamba S6 训练不稳定 | 沿用 VMamba 的学习率和 warmup 策略，梯度裁剪 |
| 编码器无 SA/CA 导致细节丢失 | 细节由跳跃连接直传解码器；解码器 SA + CA 负责细节恢复；消融实验验证 |
| SA + CA 增加参数（解码器） | 通过消融实验验证各自贡献；可单独关闭 SA 或 CA |
| CG 质心质量敏感 | 质心由 CCSM 的 FA 精炼，梯度可通过门控反向传播至 FA，形成闭环优化 |
| CCSM 编码器 vs SS2D 性能差距 | 新增编码器消融实验（CCSM vs SS2D 同解码器对比），确保不低于基线 |

## 5. 消融实验计划

1. **K 值消融：** 对比 [8,6,4,2]→[2,4,6,8]（编解码对称）vs [4,4,4,4]→[4,4,4,4]（单尺度）vs [16,12,8,4]→[4,8,12,16]
2. **SA / CA 消融：** CS-CCSM 中分别移除 SA、移除 CA、两者都移除（退化为纯 CCSM），验证各自贡献
3. **CG 消融：** CG vs 原 LGAG vs 无门控（验证质心复用门控贡献）
4. **编码器深度：** [2,2,8,2] vs [2,2,4,2] vs [2,2,12,2]
5. **vs EMCAD 基线：** 对比 MSCAM+LGAG vs CS-CCSM+CG（同编码器下解码器对比）
6. **编码器类型消融（新增）：** CCSM Encoder vs SS2D Encoder（同解码器），验证 cluster-centric 编码器至少不输 SS2D，同时参数量更少
7. **质心共享消融：** CG 使用独立质心 vs 复用 CS-CCSM 质心
